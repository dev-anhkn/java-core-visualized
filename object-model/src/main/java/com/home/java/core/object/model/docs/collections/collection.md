# Collection là gì?- Collection là interface gốc trong Java Collections Framework dùng để biểu diễn một tập hợp các phần tử (group of  objects).- Nó nằm ở nhánh trung tâm của framework:  ``` java  Iterable  └── Collection  ├── List  ├── Set  └── Queue  ```- Map không thuộc Collection.1. Bản chất của Collection    - Về mặt tư duy, Collection chỉ trả lời một câu hỏi rất nền tảng: “Làm thế nào để quản lý nhiều object như một khối      thống nhất?”    - Thay vì làm việc với từng biến riêng lẻ:        ``` java        String a = "A";        String b = "B";        String c = "C";        ```      ta gom chúng lại: Collection<String> data = ...;    - Từ đó có thể:        - thêm phần tử        - xoá phần tử        - kiểm tra tồn tại        - duyệt toàn bộ phần tử        - biết số lượng phần tử        - xử lý hàng loạt    - Nói cách khác, Collection là abstraction cho container chứa object.2. Collection là interface, không phải class    - Collection không tự lưu dữ liệu.    - Nó chỉ định nghĩa:        - tập hợp dữ liệu phải có những hành vi gì        - các implementation phải tuân theo contract nào    ``` java      public interface Collection<E> extends Iterable<E> {      int size();      boolean isEmpty();      boolean contains(Object o);      Iterator<E> iterator();      boolean add(E e);      boolean remove(Object o);      void clear();      }    ```    - Nghĩa là:        - Collection không quan tâm dữ liệu lưu bằng mảng, linked nodes hay hash table        - nó chỉ quan tâm: “một tập hợp phần tử thì tối thiểu phải làm được gì?”    - Đây chính là sức mạnh của interface:    - tách what khỏi how    - người dùng code theo abstraction    - implementation có thể thay đổi mà code phía trên ít bị ảnh hưởng3. Collection khác Collections như thế nào?    - Collection: interface    - Collections: là utility class        - Collections.sort(list);        - Collections.emptyList();        - Collections.unmodifiableCollection(c);    - Một bên là kiểu dữ liệu trừu tượng, một bên là bộ hàm tiện ích.4. Quan hệ giữa Collection và Iterable    - Collection kế thừa Iterable, nên mọi Collection đều dùng được trong for-each.    - Bản chất for-each hoạt động nhờ: Iterator<E> iterator();    - Điều này cho thấy:        - Collection không chỉ là “thùng chứa dữ liệu”        - nó còn phải hỗ trợ cơ chế duyệt tuần tự5. Các nhóm con chính của Collection    - List: ArrayList, LinkedList    - Set: HashSet, LinkedHashSet, TreeSet    - Queue: LinkedList, PriorityQueue, ArrayDeque6. Vì sao Map không thuộc Collection?    - Vì Collection quản lý từng phần tử đơn lẻ.    - Ví dụ: Collection<String> mỗi phần tử là một object.    - Còn Map quản lý cặp key-value: Map<String, Integer>    - Mỗi entry không phải chỉ là “một element” theo nghĩa đơn giản của Collection. Nên Map được thiết kế thành một      nhánh riêng.    - Tuy nhiên Map có thể cung cấp các view dạng collection:        - keySet()        - values()        - entrySet()7. Các operation cốt lõi của Collection    - Query operations: Dùng để hỏi trạng thái:        - size()        - isEmpty()        - contains(Object o)    - Modification operations: Dùng để thay đổi dữ liệu:        - add(E e)        - remove(Object o)        - clear()    - Bulk operations: Dùng để thao tác hàng loạt:        - addAll(Collection<? extends E> c)        - removeAll(Collection<?> c)        - retainAll(Collection<?> c)        - containsAll(Collection<?> c)    - Array operations: Chuyển sang mảng:        - toArray()        - toArray(T[] a)    - Traversal: Duyệt dữ liệu:        - iterator()8. Collection và equality của phần tử    - Nhiều method của Collection phụ thuộc vào equals():        - contains(o)        - remove(o)    - Có tìm thấy hay không phụ thuộc vào cách class User override equals().    - Collection hoạt động đúng hay không không chỉ phụ thuộc vào chính nó, mà còn phụ thuộc vào contract của phần tử      bên trong.9. Optional operations là gì?    - Không phải mọi implementation đều hỗ trợ mọi thao tác thay đổi dữ liệu.    - Ví dụ:        - collection chỉ đọc        - fixed-size collection        - unmodifiable collection    - Nên trong Java, một số method trong Collection là optional operation.    - Nếu implementation không hỗ trợ, nó ném: **UnsupportedOperationException**    - Ví dụ:      ``` java      Collection<String> c = List.of("A", "B");      c.add("C"); // UnsupportedOperationException      ```    - Điều này nghĩa là:        - method có tồn tại trong interface        - nhưng implementation cụ thể có thể từ chối hỗ trợ10. Collection không định nghĩa semantics cụ thể về ordering (ngữ nghĩa)    - Interface Collection chỉ nói: đây là tập hợp phần tử    - Nó không đảm bảo:        - có thứ tự hay không        - có sắp xếp hay không        - có trùng lặp hay không        - có truy cập index hay không    - Những semantics đó được đẩy xuống các sub-interface:        - List → ordered, indexed, duplicates allowed        - Set → unique elements        - Queue → processing order11. Những hiểu lầm thường gặp về Collection    - Hiểu lầm 1: Collection là class cha của mọi cấu trúc dữ liệu <> Sai. Nó là interface, không phải base class lưu      logic thực thi.    - Hiểu lầm 2: Map thuộc Collection <> Sai. Map là nhánh riêng.    - Hiểu lầm 3: mọi Collection đều có thứ tự <> Sai. Set thường không đảm bảo thứ tự như List.    - Hiểu lầm 4: Collection luôn cho sửa dữ liệu <> Sai. Có thể là unmodifiable.    - Hiểu lầm 5: contains() luôn nhanh <> Sai. Tốc độ phụ thuộc implementation:        - ArrayList.contains thường O(n)        - HashSet.contains thường O(1) trung bình12. Góc nhìn thiết kế sâu hơn    - Collection là ví dụ rất điển hình của tư duy thiết kế API tốt trong Java:        - Abstraction trước implementation        - Người dùng làm việc với “tập hợp”, không phải với chi tiết lưu trữ.    - Interface segregation theo semantics        - List, Set, Queue tách ra vì mỗi loại có bản chất khác nhau.    - Code reuse qua contract chung: Rất nhiều thuật toán có thể viết cho Collection<?> thay vì từng class riêng.    - Đa hình thực dụng: Cùng một API, nhiều cách hiện thực khác nhau với trade-off khác nhau.13. Chốt cốt lõi cần nhớ    1. Collection là interface gốc đại diện cho một nhóm phần tử.    2. Nó định nghĩa các hành vi chung nhất của một container dữ liệu.    3. Nó không quan tâm cách lưu trữ cụ thể.    4. List, Set, Queue là các specialization của Collection.    5. Map không thuộc Collection.    6. Sức mạnh lớn nhất của Collection là giúp ta code theo abstraction thay vì implementation.
