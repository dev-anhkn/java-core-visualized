# Equals trong Java – Ghi chú chuyên sâu1. `equals()` là gì?    - `equals()` là method dùng để kiểm tra **hai object có được xem là "bằng nhau" về mặt logic hay không**.      Nó được khai báo trong class gốc `java.lang.Object`:    ``` java      public boolean equals(Object obj) {          return (this == obj);      }    ```    - Điều đó có nghĩa là:        - Mặc định, `equals()` của `Object` **so sánh địa chỉ tham chiếu**        - Tức là bản chất mặc định của `equals()` giống với `==` khi áp dụng cho object2. `==` và `equals()` khác nhau thế nào?    - `==`:        - Với object, `==` so sánh: hai biến reference có trỏ tới **cùng một object trong memory** hay không        ``` java            User u1 = new User("Alice");            User u2 = new User("Alice");            System.out.println(u1 ==u2); // false        ```        - Vì:            - `u1` trỏ tới object A            - `u2` trỏ tới object B            - dù dữ liệu giống nhau, nhưng là **2 object khác nhau**    - `equals()`        - Nếu không override: vẫn so sánh như `==`        - Nếu override: có thể định nghĩa lại khái niệm “bằng nhau” theo **nội dung**3. Bản chất mặc định của `equals()`    - Method mặc định của `Object`:   ``` java   public boolean equals(Object obj) {   return (this == obj);   }   ```    - `this == obj` nghĩa là: object hiện tại (`this`) và object truyền vào (`obj`) có cùng địa chỉ hay không    - Vì vậy: > Mặc định trong Java, object chỉ được coi là bằng nhau khi chúng là **cùng một object**. Đây là *      *identity equality**.4. Khi nào cần override `equals()`?    - Cần override khi class của bạn có khái niệm:        - hai object khác nhau về địa chỉ        - nhưng giống nhau về mặt dữ liệu / business meaning            - hai `User` có cùng `id`            - hai `Person` có cùng `name` và `age`            - hai `Money` có cùng `amount` và `currency`        - Khi đó, “bằng nhau” không còn là cùng địa chỉ nữa, mà là **logical equality**.5. Ví dụ chưa override `equals()`    ``` java    class User {        String name;        User(String name) {            this.name = name;        }    }    ```    ``` java    User u1 = new User("Alice");    User u2 = new User("Alice");    System.out.println(u1.equals(u2)); // false    ```    - Giải thích:        - `User` không override `equals()`        - nên nó dùng `equals()` của `Object`: thực chất là `u1 == u2`        - mà `u1` và `u2` là 2 object khác nhau -> Nên kết quả là `false`.6. Override `equals()` để so sánh nội dung   ``` java   import java.util.Objects;   class User {       String name;       User(String name) {           this.name = name;       }       @Override       public boolean equals(Object obj) {           if (this == obj) return true;           if (obj == null || getClass() != obj.getClass()) return false;           User other = (User) obj;           return Objects.equals(name, other.name);       }   }   ```    - Khi đó:   ``` java   User u1 = new User("Alice");   User u2 = new User("Alice");   System.out.println(u1.equals(u2)); // true   ```    - Vì:        - `u1` và `u2` khác địa chỉ        - nhưng `name` của cả hai cùng là `"Alice"`        - logic equals mới định nghĩa rằng: 2 `User` bằng nhau nếu `name` bằng nhau        -7. Contract của `equals()` (Quy ước):    - Reflexive: Một object luôn bằng chính nó.    - Symmetric: Nếu `x.equals(y)` là `true`, thì `y.equals(x)` cũng phải là `true`.    - Transitive: Nếu `x.equals(y)` và `y.equals(z)` đều `true`, thì `x.equals(z)` cũng phải `true`.        - Consistent: Nếu dữ liệu không đổi, gọi `equals()` nhiều lần phải ra cùng kết quả.8. Non-null    - Với mọi object `x`   ``` java      x.equals(null) ==false   ``` 9. Vì sao contract quan trọng?    - Vì rất nhiều API trong Java dựa vào khái niệm equality ổn định.    - Nếu viết sai `equals()`:        - collection có thể hoạt động sai        - dữ liệu trùng có thể không phát hiện được        - tìm kiếm / xóa object có thể lỗi logic        - code trở nên khó debug10. Dùng `getClass()` hay `instanceof`?    - `getClass()`        ``` java           if (obj ==null|| getClass() !=obj.getClass()) return false;        ```        - Ý nghĩa: chỉ cho phép bằng nhau khi **đúng cùng class**        - Ưu điểm:            - chặt chẽ            - tránh rắc rối với kế thừa    - `instanceof`        ``` java              if(!(obj instanceof User))return false;        ```        - Ý nghĩa: cho phép object subclass cũng được coi là cùng loại để so sánh        - Ưu điểm:            - linh hoạt hơn        - Nhược điểm: dễ phá vỡ tính đối xứng nếu class cha/con cùng override `equals()` không cẩn thận. Ở mức học nền          tảng, với class domain thông thường, dùng `getClass()` thường an toàn và dễ hiểu hơn.11. `equals()` với immutable object và mutable object    - Immutable object        - Ví dụ: `String`, `Integer`, `LocalDate`            - dữ liệu không đổi sau khi tạo            - `equals()` ổn định            - an toàn hơn để dùng làm identity logic    - Mutable object        - Ví dụ object có setter thay đổi field            - kết quả `equals()` có thể thay đổi theo thời gian            - dễ gây bug nếu object được dùng trong collection hoặc luồng logic dài# Tổng kết bản chất### Gói gọn trong vài ý:1. `equals()` mặc định của `Object` chỉ so sánh địa chỉ:2. Muốn so sánh nội dung thì phải override.3. Override `equals()` là đang định nghĩa lại: thế nào là “bằng nhau” về mặt logic cho class đó.4. Khi override `equals()` thì gần như luôn phải override `hashCode()`.5. `equals()` đúng không chỉ là viết đúng cú pháp, mà là định nghĩa đúng **bản chất identity logic** của object.
