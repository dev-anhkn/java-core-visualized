# ArrayList trong Java1. `ArrayList` là gì?    - Là một class    - Là một **implementation của `List`**.    - Là một **Danh sách mảng động (Dynamic Array)** -> để chứa các phần tử.    - Ý quan trọng nhất:      > Bản chất của nó là **một lớp bọc quản lý một mảng có thể tự nới ra khi cần**.    - ArrayList không phải là mảng, mà là một abstraction quản lý mảng.2. Bản chất cốt lõi    - **Lưu phần tử trong mảng**: Bên dưới có một Object[].    - **Size**: Đây là số phần tử thực sự đang có trong list.    - **Capacity**: Đây là kích thước mảng backend hiện tại.3. size và capacity khác nhau thế nào?    - size: Là số phần tử logic mà List đang chứa.    - capacity: Là số ô của mảng backend hiện tại.        ``` java        List<String> list = new ArrayList<>();        list.add("A");        list.add("B");        list.add("C");        ```        - elementData = ["A", "B", "C", null, null, null, null, null, null, null]        - size = 3        - capacity = 10    - Tức là:        - list đang có 3 phần tử        - nhưng mảng bên dưới đang có chỗ cho 10 phần tử4. Vì sao gọi là “dynamic array”?    - Vì mảng Java bình thường có kích thước cố định:      ``` java      String[] arr = new String[10];      ```    - Sau khi tạo xong thì không thể “nới” mảng đó.    - Còn ArrayList tạo cảm giác như có thể lớn lên vô hạn.    - Thực ra nó không kéo dãn mảng cũ. Nó làm theo cách này:        - có một mảng cũ        - khi mảng đầy, tạo một mảng mới lớn hơn        - copy dữ liệu từ mảng cũ sang mảng mới        - trỏ sang mảng mới    - Nên đúng bản chất là: ArrayList không làm mảng “to lên”, mà thay mảng cũ bằng mảng mới lớn hơn.5. Thêm phần từ đầu tiên   ``` java   List<String> list = new ArrayList<>();   list.add("A");   ```    - Kiểm tra xem có đủ sức chứa không (lần đầu tiên size = capacity)    - Kiểm tra tiếp capacity = 0 (mảng rỗng mặc định) -> JDK sẽ cấp phát mảng mới với default capacity = 10    - sau đó với thêm phần tử vào elementData[0] = "A"6. Thêm phần tử vào cuối hoạt động thế nào?    - [A, B, C, null, null]        - size = 3        - Khi: list.add("D");        - thì ArrayList chỉ cần:            - gán "D" vào elementData[3]            - tăng size lên 4        - Sau đó:            - [A, B, C, D, null]            - size = 4    - Thao tác này rất rẻ.7. Khi mảng đầy thì chuyện gì xảy ra?    - [A, B, C]        - size = 3        - capacity = 3    - Bây giờ gọi:        - list.add("D");        - Không còn chỗ nữa, nên ArrayList phải:            1. tạo mảng mới lớn hơn (oldCapacity >> 1) - dễ hiểu thì là ~~ * 1.5            2. copy A, B, C sang mảng mới            3. thêm D            4. cập nhật elementData    - add(e) thường nhanh, nhưng có những lúc đột nhiên đắt vì phải resize + copy.8. Vì sao add(e) thường được coi là O(1)?    - Không phải mỗi lần thêm đều resize.    - Phần lớn thời gian, nó chỉ làm:        - elementData[size] = e        - size++    - -> rất nhanh, gần O(1)    - Chỉ thi thoảng mới gặp resize, lúc đó tốn O(n) để copy.    - Vì vậy người ta nói: add(e) của ArrayList là amortized O(1)    - Tức là:        - có vài lần rất đắt        - nhưng nếu nhìn trung bình trên nhiều lần add thì chi phí mỗi lần vẫn gần O(1)9. Vì sao chèn vào giữa lại chậm?    - [A, B, C, D]    - list.add(1, "X");    - Mong muốn: [A, X, B, C, D]    - Muốn vậy thì các phần tử từ index 1 trở đi phải dịch sang phải:        - D sang ô mới        - C sang ô mới        - B sang ô mới        - Rồi mới đặt X vào index 1.    - Nên: chèn giữa = phải shift dữ liệu => chi phí thường là O(n)10. Vì sao xóa giữa cũng chậm? - tương tự chèn (add) thêm còn giảm size11. Tại sao phải gán null cho slot thừa?    - [A, B, C, D, null]        - size = 4        - Xóa D thì nếu chỉ giảm size mà không gán:            - elementData[3] = null;            - thì mảng vẫn giữ reference tới object cũ.            - Điều đó làm object không được GC giải phóng dù về mặt logic list không còn chứa nó nữa.            - Nên ArrayList phải clear reference thừa để tránh giữ object sống vô ích.            - Đây không phải “memory leak” kiểu C/C++, nhưng là giữ reference thừa không cần thiết.12. ArrayList lưu object thật hay lưu reference? -> Nó lưu reference.    - Tức là:        - ArrayList không clone object        - nó chỉ giữ tham chiếu tới object đó13. contains() có nhanh không? -> Không.    - Nó phải duyệt từng phần tử rồi so sánh bằng equals(). => contains() là O(n)    - Tức là:        - truy cập theo vị trí nhanh        - nhưng tìm theo giá trị thì không nhanh14. indexOf() và lastIndexOf() hoạt động thế nào?    - indexOf duyệt từ đầu đến cuối    - lastIndexOf duyệt từ cuối về đầu    - Cả hai đều là O(n)15. ArrayList có thread-safe không? - Không.16. Khi nào ArrayList không phù hợp?    - Khi bài toán có pattern như:        - chèn đầu liên tục        - xóa đầu liên tục        - chèn/xóa giữa quá thường xuyên        - nhiều thread cùng sửa mà không kiểm soát        - list rất lớn và hay resize/shift
